# Plan: show the app version on the home screen (issue #78)

## Goal

Issue [#78](https://github.com/darkcosmos/kosmo-darts/issues/78): the home screen shows, discreetly, which build is
installed ("Version 0.1.0 (build 123)"), so that Kosmo knows which PR build he is testing. French and English. It
must not hinder any home button, in portrait and landscape.

## Scope and out of scope

In scope:
- A CI build number baked into the APK at build time (`GITHUB_RUN_NUMBER`, local fallback `dev`).
- A fixed footer on the home screen with the version line, in every build type (debug and release).
- Rule identifiers AV1 to AV3 in `docs/rules/history.md`, tests citing them, captures updated.

Out of scope:
- Any change to `.github/**` (the workflow already exports `GITHUB_RUN_NUMBER` to every step).
- Changing `versionName` or `versionCode` (still `0.1.0` and `1`), release signing, the backlog item "real release
  version".
- Showing the version anywhere else (Settings, History, match detail).
- Screens smaller than a Pixel 7.

## Approach

1. Build (`app/build.gradle.kts`): `buildFeatures { buildConfig = true }`, and in `defaultConfig` a
   `buildConfigField("String", "BUILD_NUMBER", ...)` whose value is
   `providers.environmentVariable("GITHUB_RUN_NUMBER")`, trimmed, then kept only when
   `Regex("[0-9]{1,10}").matches(value)` (full match), else `"dev"`. The check is inline in the build script (one
   expression, no separate function; Decisions D7). The provider API keeps the configuration cache correct; the
   full-match digit check means no arbitrary text ever enters generated Java source. `BuildConfig.VERSION_NAME`
   (generated by AGP from `versionName`) gives the version part.
2. UI: `HomeScreen` gains two plain `String` parameters, `versionName` and `buildNumber`. Its root becomes a
   `Column` inside the safe drawing area: the existing scrolling column with `weight(1f)`, then a footer `Text`
   (`home_version` resource, `KosmoTheme.typography.body` (16sp), `KosmoTheme.colors.onBackgroundMuted`, centered,
   `maxLines = 2`, `overflow = TextOverflow.Clip`, never an ellipsis, test tag `HomeTags.VERSION`). The footer is
   outside the scroll, so it is always visible and never overlaps a button: the scroll viewport simply ends above it.
   One line at font scale 1; at font scale 2 "Version 0.1.0 (build 12345)" (about 27 characters at 32sp, wider than
   the 388dp of a Pixel 7 in portrait) may wrap to a second line, which is allowed (Decisions D8).
   Two loose `String` parameters are kept rather than a holder type (architecture A1: acceptable, smallest change).
3. Wiring: `KosmoDartsApp` passes `BuildConfig.VERSION_NAME` and `BuildConfig.BUILD_NUMBER` to `HomeScreen`; its own
   signature does not change, so `MainActivity` and `CricketSystemBarsTest` are untouched.
4. Tests and captures call `HomeScreen` with fixed values (`"0.1.0"`, `"123"`), so captures do not change from one CI
   run to the next.

Alternatives considered:
- Version from `PackageManager` (`KosmoDartsApplication.appVersion()`): it only gives `versionName`, not the build
  number, and would need plumbing through the ViewModel. Rejected.
- Put the build number into `versionName` (`0.1.0+123`): it would also change the archived version (AR5) and the
  Android settings app; Kosmo's format keeps the two parts separate. Rejected (see Decisions D3).
- `versionCode = GITHUB_RUN_NUMBER`: not needed to display it, and touches upgrade semantics. Rejected.

## Data read, stored or exposed

- Read at build time: the `GITHUB_RUN_NUMBER` environment variable (a public run counter, not a secret).
- Stored: nothing new. The archived app version (AR5, D31) stays `versionName` only (Decisions D3).
- Exposed: the version line on screen. No permission, no network.

## Screens and states

Home screen only, with and without a saved game, portrait and landscape, English and French, font scale 1 and 2.
The footer is one centered line at the bottom, above the navigation bar; the content above scrolls as before.
Dialogs (new game confirmation) are unchanged and draw over the footer.

## Test plan

Rules AV1 to AV3 (`docs/rules/history.md`, written in T1):
- AV1: the footer text is "Version <versionName> (build <buildNumber>)" in English and French.
- AV2: the build part is the CI run number (1 to 10 digits after trimming); `dev` otherwise, including local
  builds; shown in every build type.
- AV3: the footer is fixed (outside the scroll) and every home control stays reachable above it.
The archived app version is not a rule of this mission: it is unchanged (Decisions D4).

Cases:
- T1 `BuildNumberTest` (plain JUnit): `BuildConfig.BUILD_NUMBER` fully matches `[0-9]{1,10}|dev` (AV2). No assertion
  against the environment, so it passes on any machine.
- T1 build-script filter, checked by a scripted loop (Decisions D7): for each value of `GITHUB_RUN_NUMBER`, run
  `./gradlew :app:generateDebugBuildConfig` and read `BUILD_NUMBER` in the generated `BuildConfig.java`. Expected:
  unset -> `dev`; `""` -> `dev`; `"123"` -> `123`; `"0123"` -> `0123`; `"12a"` -> `dev`; `"1 2"` -> `dev`; `"-5"` ->
  `dev`; `"12\n"` -> `12`; `"12 "` -> `12`; `"1234567890"` -> `1234567890`; `"12345678901"` -> `dev`. The output of
  the loop is pasted into the T1 implementation notes.
- T2 `HomeScreenTest` (through `MainActivity`): the footer text equals
  `getString(R.string.home_version, BuildConfig.VERSION_NAME, BuildConfig.BUILD_NUMBER)` (AV1, AV2), never a
  hard-coded copy of the format.
- T2 `HomeVersionFooterTest` (Robolectric, Pixel 7, `HomeScreen` with `"0.1.0"` and `"12345"`, a 5-digit build
  number), for `+en-port`, `+fr-port`, `+en-land`, `+fr-land`, each at font scale 1 and 2, with and without a saved
  game (a 4-player X01 match, the longest card):
  - the footer text equals the fixed literal of the current language, e.g. "Version 0.1.0 (build 12345)" (AV1);
  - via the `GetTextLayoutResult` semantics action (as `HomeFitTest.layoutOf` does): `lineCount == 1` at font scale
    1, `lineCount <= 2` at font scale 2, `hasVisualOverflow == false` and the last line ends with "12345)" (never cut,
    never ellipsized) (AV1, AV3);
  - the footer is displayed, inside the window and above the bottom safe area (AV3);
  - the footer does not move when the column scrolls (it is not a descendant of the scroll container) (AV3);
  - for each of settings, resume card, X01, Cricket and History: `performScrollTo()`, then its bounds lie fully
    above the footer top, it is displayed, has a click action and is at least 48dp tall (or 42dp in landscape,
    CLAUDE.md exception) (AV3).
- T2 `FrenchStringsTest`: `home_version` in French and both files define it (AV1).
- T2 `PaletteContrastTest`: `onBackgroundMuted` on `background` is at least 4.5:1 (the footer, 16sp regular text;
  #AEB8D6 on #0A0F1E).
- T2 `HomeFitTest`: existing U6 and U7 cases still pass with the new parameters.
- Captures: `HomeScreenScreenshotTest` (five captures) show the footer with fixed values; `HistoryScreenshotTest`
  and `CricketSetupScreenshotTest` only gain the parameters.

## How Kosmo verifies

On his Pixel 7, with the debug APK built by the CI for the latest commit, after uninstalling the previous version:
1. Open the app: at the bottom of the home screen, "Version 0.1.0 (build N)", where N is the run number of the CI
   build he downloaded (shown in the GitHub Actions run title as "#N").
2. Switch the phone to French: the line is in French.
3. Turn to landscape: the line stays at the bottom; scroll the home screen: every button (settings, game in
   progress, X01, Cricket, History) can be reached and tapped, none hidden under the line.
4. With a game in progress, repeat step 3.

## Decisions

- D1 (Kosmo, Q1 = b): the line is "Version <versionName> (build <CI run number>)"; local builds show `dev` as the
  build part. `.github/**` is not changed: `app/build.gradle.kts` reads `GITHUB_RUN_NUMBER`.
- D2 (Kosmo, Q2 = b): fixed footer at the bottom of the home screen, outside the scroll; tests prove every home
  control stays reachable in portrait and landscape on a Pixel 7, at font scale 1 and 2.
- D3 (Kosmo, Q3): the build number is shown in every build type, release included; no debug-only gating.
- D4 (plan): `versionName` is unchanged, so the version archived with each match (AR5, D31) stays `0.1.0`, without
  the build number. Effect on archived data: none. This is a statement of non-change, not a rule: the archive path
  (`KosmoDartsApplication.appVersion()`, `PackageManager` `versionName`) is not touched, so no AV rule and no new
  test (design review T1, architecture addendum: no test that needs new plumbing).
- D5 (plan, design review S1): `GITHUB_RUN_NUMBER` is trimmed, then kept only on a full match of `[0-9]{1,10}`;
  anything else gives `dev`. Nothing but digits enters generated source.
- D6 (plan): the composable takes plain `String`s; tests and captures pass `"0.1.0"` and a fixed build number.
- D7 (design review T2 vs architecture addendum): the filter stays inline in `app/build.gradle.kts`, with no
  `resolveBuildNumber` function. A unit-testable function would have to live in `buildSrc` or an included build
  (build scripts cannot use `:app` sources, and `:game-engine` must not hold build logic): a new build structure for
  one expression. Instead, every input case listed by the test reviewer is checked against the real build script by
  the scripted `generateDebugBuildConfig` loop of the Test plan, and `BuildNumberTest` guards the shape of the
  shipped value on every build. This proves the same cases without new structure.
- D8 (plan, design review T3, U2): footer style `typography.body` in `onBackgroundMuted`; one line at font scale 1,
  up to two lines at font scale 2, never ellipsized or cut; contrast at least 4.5:1, asserted in
  `PaletteContrastTest`.
- D9 (Kosmo): French wording identical to English, "Version 0.1.0 (build 123)": `home_version` is
  "Version %1$s (build %2$s)" in both `values/` and `values-fr/` ("build", not "compilation").
